# ADR 0026: ハーネスのモデル戦略＝精度優先（Fable 頭を廃し独立敵対レビューをゲート化）

- 状態: 廃止（後継 [[0031-model-strategy-cursor-multi-family]]）（廃止対象: AGENTS.md「モデル戦略（Fable 頭）」）
- 日付: 2026-07-06
- 背景: 開発ハーネス（Claude Code）の頭を **Fable 5** に置いていた（安価に大量オーケストレーション）。
  だが運用は **Max 5 プラン**でコストが制約でなくなり、目的は「出費最小」から**出力の精度担保**に一本化した。
  ここで効く事実: **精度は"1席あたりのモデルの大きさ"ではなく"独立した検証の深さ"で決まる**。
  同一 context で「書いて→自分で確認」は著者が自分の誤りに盲目で精度が上がらない。
- 決定: **精度優先のモデル戦略に転換**。Fable を全席から廃止。
  - **頭（計画/統合/ディスパッチ/内省）= Opus 4.8**。推論最優先。コスト目的だった「頭を実装から隔離する規律」は
    精度目的では不要——Opus が計画も実装も跨いでよい。**ただし検証だけは常に独立**（下記・不変条件）。
  - **実装**: 高リスク・非自明ロジック = **Opus**。純ボイラープレート/機械作業のみ Sonnet/Haiku に委譲可、
    ただし下の独立レビューは免除しない。
  - **独立敵対レビュー（全変更のデフォルトゲート）**: **実装とは別の agent 呼び出し・fresh context・敵対的
    プロンプト**（「チェックして」ではなく「壊せ／どこが間違っているか探せ」）を Opus で走らせる。既存
    `security-reviewer`（Opus・敵対的）を全変更に一般化。`verifier` は Sonnet→**Opus** に格上げ。
  - **高リスク検証（認証/課金/セキュリティ/アーキ）**: 独立 Opus を **3体・多レンズ（correctness / テナント越境 /
    IDOR / secret漏れ）で多数決**、**過半数が確認するまで前進不可**。fan-out は Workflow（多agent）で実行時に明示起動。
  - **内省（reflector）= Opus**。自己成長ループの複利核であり品質が直接効くため確定で Opus。
  - **不変条件**: レビューは**必ず実装と独立した fresh context・敵対的**であること。同一 context の自己確認で
    前進段を満たしたと見なさない。単独敵対レビューを全変更に、3体多数決を高リスクに掛ける（精度/ノイズの均衡）。
- 結果: 頭の推論品質と検証の独立性が上がる。Max プランの余剰を"独立検証の冗長化"に振り向け、
  「Sonnet で安く書いて浮かす」設計を捨てる。将来コストが制約化した時のみ [[0024-autonomy-modes]] と連動した
  モード別頭モデル（自動/長時間=安モデル頭）を再検討する余地は残す。
